# StateDock development

Keep task/project semantics in the shared core and deployment concerns in adapters. Preserve tenant boundaries, owner-only project settings, OAuth scopes and instance-administrator isolation.

For meaningful implementation goals use the connected StateDock instance when available; read existing goals first and leave concise results in the user's language. Do not guess an official Cloud connection for a self-deployed project.

Do not commit personal deployment configs, secrets, real account data, database exports or generated caches. Use the existing checks in README. Public visibility and release publishing are separate actions from code preparation.
